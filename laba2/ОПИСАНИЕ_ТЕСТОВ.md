# Описание тестов для отчёта — Лабораторная работа 2

Приложение: «Магазин мебели» (Django).  
Тесты расположены в `shop/tests/`.  
Запуск: `uv run python manage.py test --noinput`.

Используются `SimpleTestCase` (без тестовой БД) и `TestCase` (тестовая БД Django + HTTP-клиент).

---

## 1. `test_services.py` — расчёт скидки (`ApplyDiscountTests`)

Проверяется функция `apply_discount` (цена до копеек, округление половины вверх). Без тестовой БД.

| Тест | Что проверяется |
| --- | --- |
| `test_zero_discount_keeps_price` | Скидка 0% не меняет цену |
| `test_none_and_empty_discount_mean_zero` | `None` и пустая строка считаются нулевой скидкой |
| `test_basic_percent` | 1000 − 10% = 900.00 |
| `test_full_discount` | 100% → цена 0.00 |
| `test_half_discount` | 50% от 200 = 100.00 |
| `test_accepts_decimal_and_string_price` | Цена может быть `Decimal` или строкой |
| `test_rounds_half_up_to_kopecks` | 0.125 → 0.13 (не банковское округление) |
| `test_fractional_percent_is_not_truncated_to_rubles` | 999 − 10% = 899.10, а не 900 |

## Выводы

Тесты фиксируют правила магазина:

- скидка не поднимается выше 50%;
- в каталоге и заказе цена считается до копеек;
- в покупку записывается снимок цены и процента скидки на момент заказа;
- чужие заказы в профиле не видны;
- пустой адрес и отсутствующий товар заказ не создают;
- удаление покупателя удаляет его покупки;
- товар с покупками удалить нельзя.

Тесты скидки и адресов проверяют чистый расчёт и маршруты без тестовой базы. Остальные тесты проходят через тестовую БД Django и HTTP-клиент.
